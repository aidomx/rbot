# Desain Konversi Makefile ke Buildfile (`rbot -xf make`)

## Tujuan

Menyediakan jalur migrasi yang mulus bagi developer C/C++ yang ingin beralih dari Makefile ke ekosistem `rbot`. Perintah `rbot -xf make` akan mengekstrak konfigurasi deklaratif dari Makefile dan mengubahnya menjadi format `Buildfile` yang bersih, ringkas, dan mudah dibaca.

## Filosofi: "Declarative Extraction" (Ekstraksi Deklaratif)

Makefile adalah bahasa prosedural (Turing-complete), sedangkan `Buildfile` adalah bahasa deklaratif.
**Aturan Emas:** Konverter **TIDAK** akan mencoba menerjemahkan 100% logika Makefile (seperti loop, conditional `ifeq`, atau skrip shell). Konverter hanya akan mengekstrak **konfigurasi statis dan deklaratif** (compiler, flags, sources, libraries).

Logika prosedural yang kompleks akan diabaikan dan diganti dengan komentar peringatan di akhir file. Ini menjaga core `rbot` tetap ringan dan hasil konversi tetap bersih dari _boilerplate_.

## 1. Integrasi CLI (`rbot.c`)

Fitur ini memanfaatkan infrastruktur `-xf` dan `-xcf` yang sudah ada di `rbot.c`.

### Resolusi Argumen

- Jika user mengetik `rbot -xf make`, sistem akan mencari file bernama `Makefile`, `makefile`, atau `GNUmakefile` di direktori saat ini.
- Jika user mengetik `rbot -xf path/to/MyMakefile`, sistem menggunakan path tersebut secara langsung.

### Perilaku Output

- **`-xf make`**: Hasil konversi ditulis ke file sementara `Buildfile.xf.tmp`. File ini akan dihapus otomatis setelah command selesai. (Aman untuk preview).
- **`-xcf make`**: Hasil konversi ditulis ke `Buildfile`. Jika `Buildfile` sudah ada, sistem akan meminta konfirmasi interaktif sebelum menimpa.

## 2. Aturan Pemetaan (Mapping Rules)

Konverter akan memindai Makefile baris demi baris, mencari variabel standar, dan memetakannya ke DSL `Buildfile`.

| Variabel Makefile | Pola Pencarian                               | Output Buildfile          | Contoh Transformasi                           |
| :---------------- | :------------------------------------------- | :------------------------ | :-------------------------------------------- |
| **Compiler**      | `CC = ...`, `CXX = ...`                      | `compiler = ...`          | `CC=gcc` -> `compiler = gcc`                  |
| **Flags**         | `CFLAGS`, `CXXFLAGS`, `CPPFLAGS`             | `flags = ...`             | `-Wall -O2` -> `flags = Wall, O2`             |
| **Standard**      | `-std=c11`, `-std=c++17` (di dalam flags)    | `std = ...`               | `-std=c++17` -> `std = c++17`                 |
| **Headers**       | `-I./include`, `-Isrc` (di dalam flags)      | `headers = ...`           | `-Iinclude` -> `headers = include`            |
| **Libraries**     | `LDLIBS`, `LDFLAGS` (bagian `-l`)            | `library = ...`           | `-lssl -lcrypto` -> `library = ssl, crypto`   |
| **Sources**       | `SRCS = ...`, `SOURCES = ...`                | `sources = ...`           | `SRCS=main.c` -> `sources = main.c`           |
| **Target**        | `TARGET = ...` atau rule utama `app: main.o` | `output.binaryName = ...` | `TARGET=myapp` -> `output.binaryName = myapp` |

### Logika Parsing Detail

1. **Pemisahan Flag:** Jika `CFLAGS` berisi `-Wall -I./include -std=c++17`, parser harus memisahkannya:
   - `-Wall` -> masuk ke `flags`
   - `-I./include` -> masuk ke `headers` (hilangkan prefix `-I`)
   - `-std=c++17` -> masuk ke `std` (hilangkan prefix `-std=`)
2. **Pemisahan Library:** Jika `LDLIBS` berisi `-lssl -lcrypto -lpthread`, parser memisahkannya ke `library = ssl, crypto, pthread` (hilangkan prefix `-l`).
3. **Deduplikasi:** Jika `CFLAGS` dan `CXXFLAGS` memiliki flag yang sama (misal `-Wall`), gabungkan ke dalam satu baris `flags` tanpa duplikat.

## 3. Format Output (`Buildfile`)

Hasil konversi harus terlihat seperti ditulis oleh manusia, bukan mesin. Konverter akan menambahkan header komentar dan mengelompokkan konfigurasi secara logis.

**Contoh Input (`Makefile` sederhana):**

```makefile
CC = gcc
CXXFLAGS = -Wall -Wextra -O2 -std=c++17 -I./include -I./src
LDLIBS = -lssl -lcrypto -lpthread
SRCS = main.cpp app.cpp
TARGET = myapp

all: $(TARGET)
$(TARGET): $(SRCS)
	$(CC) $(CXXFLAGS) -o $@ $^ $(LDLIBS)

clean:
	rm -f $(TARGET)
```

**Contoh Output (`Buildfile` hasil `rbot -xcf make`):**

```text
# Generated by rbot -xf make
# Original file: Makefile

compiler = gcc
std = c++17
flags = Wall, Wextra, O2
headers = include, src
library = ssl, crypto, pthread

sources = main.cpp, app.cpp

output.binaryName = myapp
```

## 4. Penanganan Makefile Raksasa (Complexity Escape Hatch)

Jika konverter mendeteksi Makefile dengan kompleksitas tinggi (seperti `nmakefile.txt` Node.js yang memiliki > 500 baris, recursive make `$(MAKE)`, atau conditional `ifeq`), dia akan:

1. Mengekstrak konfigurasi global (`CC`, `CFLAGS`, `LDLIBS`, dll) ke bagian atas `Buildfile`.
2. Mengabaikan target kompleks (`test-ci`, `pkg-upload`, `coverage`, dll).
3. Menambahkan komentar peringatan eksplisit di bagian bawah file hasil konversi:

```text
# ---------------------------------------------------------
# WARNING: Makefile asli memiliki target kompleks/prosedural
# (seperti recursive make, conditional ifeq, atau skrip shell)
# yang tidak dapat dikonversi secara otomatis ke Buildfile
# deklaratif. Silakan periksa logika build kustom Anda secara manual.
# ---------------------------------------------------------
```

## 5. Implementasi Teknis

### Modul Baru: `makeconv.c` & `makeconv.h`

- Dibuat terpisah dari `ninjaconv.c` untuk menjaga isolasi kode.
- Diekspor fungsi utama: `bool makeToBuildfile(const char *srcPath, const char *dstPath, char *err, size_t errSize);`

### Strategi Parsing (State Machine Sederhana)

1. **Baca Baris demi Baris:** Gunakan `fgets`.
2. **Abaikan Resep (Recipes):** Jika baris dimulai dengan karakter Tab (`\t`), lewati. Itu adalah kode shell, bukan konfigurasi.
3. **Abaikan Komentar & Direktif:** Lewati baris yang dimulai dengan `#`, `include`, `ifeq`, `ifdef`, `else`, `endif`.
4. **Ekstraksi Variabel:** Cari pola `[A-Z_]+ = (.*)` atau `[A-Z_]+ := (.*)`.
5. **Tokenisasi:** Gunakan `strtok_r` atau parsing manual untuk memecah nilai variabel berdasarkan spasi, lalu terapkan aturan pemetaan (Mapping Rules) di Bagian 2.

## 6. Manfaat Desain Ini

1. **Zero Overhead:** Tidak ada dependency eksternal. Hanya menggunakan string manipulation standar C.
2. **Nilai Edukasi & Migrasi:** Developer yang baru menemukan `rbot` bisa langsung mengetik `rbot -xcf make` di proyek lama mereka. Dalam 1 detik, mereka melihat betapa bersihnya `Buildfile` dibandingkan Makefile mereka.
3. **Konsistensi CLI:** Menggunakan pola `-xf` yang sama dengan konversi Ninja, membuat API CLI `rbot` tetap konsisten dan mudah diingat.
